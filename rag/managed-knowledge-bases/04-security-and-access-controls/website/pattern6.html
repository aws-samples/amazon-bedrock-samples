Pattern 6

JWT + Cedar (Multi-Tenant)

Combine JWT authentication with Cedar authorization. JWT validates WHO the caller is, Cedar decides WHAT they can do. The pattern for multi-tenant applications.

Layer 1 — JWT (WHO)

  • ✓ Validates identity
  • ✓ Is this a real, authenticated user?
  • ✓ Extracts claims (department, role)

Layer 2 — Cedar (WHAT)

  • ✓ Evaluates authorization
  • ✓ Is this user allowed to invoke this gateway?
  • ✓ Per-principal permit/deny

Multi-Tenant Target Layout

# Gateway (JWT + Cedar)
#   ├── Target: engineering-kb  ← Cedar: permit dept=engineering
#   ├── Target: marketing-kb   ← Cedar: permit dept=marketing
#   └── Target: shared-kb      ← Cedar: permit all

gw = ac.create_gateway(
    name="multi-tenant-gw",
    roleArn=GW_ROLE_ARN,
    protocolType="MCP",
    authorizerType="CUSTOM_JWT",
    authorizerConfiguration={...},
    policyEngineConfiguration={
        "arn": pe_arn,
        "mode": "LOG_ONLY"  # Start with audit, then ENFORCE
    }
)
ModeBehaviorWhen to Use
LOG_ONLYCedar evaluates and logs but does not blockTesting, auditing, gradual rollout
ENFORCECedar evaluates and blocks denied requestsProduction after LOG_ONLY validation

🎯 When to Use

Multi-tenant SaaS where different users/departments have different access levels. JWT identifies the user; Cedar decides which targets they can invoke. Recommended rollout: LOG_ONLY → review CloudWatch logs → ENFORCE.
