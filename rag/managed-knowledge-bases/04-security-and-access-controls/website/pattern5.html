Pattern 5

Gateway + JWT (Cognito)

Use Cognito as the identity provider. The Gateway validates JWT tokens before allowing access to KB targets. This enables per-user identity without exposing the KB ID.

JWT Authentication Flow

  • 1. Client authenticates with Cognito → JWT
  • 2. Client sends Bearer token to Gateway
  • 3. Gateway validates via OIDC discovery
  • 4. If valid, request proceeds to KB target

Available JWT Claims

  • sub — Cognito user ID
  • email — User email
  • custom:department — Custom attribute
  • aud — App client ID
  • iss — Pool issuer URL

Create JWT Gateway

discovery_url = f"https://cognito-idp.{REGION}.amazonaws.com/{pool_id}/.well-known/openid-configuration"

gw = ac.create_gateway(
    name="jwt-gateway",
    roleArn=GW_ROLE_ARN,
    protocolType="MCP",
    authorizerType="CUSTOM_JWT",
    authorizerConfiguration={"customJWTAuthorizer": {
        "discoveryUrl": discovery_url,
        "allowedAudience": [client_id],
        "allowedClients": [client_id]
    }}
)

🎯 When to Use

When you need per-user identity without IAM. Custom claims like custom:department can be used downstream by Lambda interceptors to inject metadata filters dynamically — enabling per-user document scoping.
