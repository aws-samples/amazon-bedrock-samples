Pattern 4

Gateway + Cedar Policy Engine

Add Cedar authorization policies to the Gateway. Cedar evaluates whether a principal can invoke a specific Gateway target. Supports LOG_ONLY and ENFORCE modes.

LOG_ONLY Mode

  • ✓ Cedar evaluates and logs decisions
  • ✓ Does NOT block requests
  • ✓ Use for auditing and testing
  • ✓ Validate before enforcement

ENFORCE Mode

  • ✓ Cedar evaluates and blocks denied
  • ✓ Production-ready enforcement
  • ✓ 403 Forbidden on deny
  • ✓ Use after LOG_ONLY validation

Cedar Policy Examples

// Permit all principals to invoke this gateway
permit(principal, action,
  resource == AgentCore::Gateway::"<gateway-arn>");

// Deny a specific principal
forbid(
  principal == AgentCore::Principal::"arn:aws:iam::123456789012:role/DeniedRole",
  action,
  resource == AgentCore::Gateway::"<gateway-arn>"
);

Cedar Controls

  • ✓ Whether a principal can invoke a Gateway
  • ✓ Resource-level permit/deny
  • ✓ Gateway-level access

Cedar Does NOT Control

  • ✗ Which documents are returned
  • ✗ Document-level filtering
  • ✗ Metadata filter scoping

🎯 When to Use

When you need per-principal authorization with policy-as-code. Cedar controls WHO can invoke the Gateway (resource-level). For document-level scoping, combine Cedar with metadata filters (Pattern 2).
