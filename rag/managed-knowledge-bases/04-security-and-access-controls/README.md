# Managed Knowledge Bases — Security Patterns

Jupyter notebooks demonstrating security patterns for Amazon Bedrock Managed Knowledge Bases, from direct SDK access to full governance with AgentCore Gateway, Cedar policies, JWT authentication, and Lambda interceptors.

## Patterns

| # | Notebook | Description | Complexity |
|---|---|---|---|
| 1 | `01-direct-sdk.ipynb` | Direct SDK access with IAM — no Gateway | ⭐ |
| 2 | `02-metadata-filters.ipynb` | Metadata filtering for document-level scoping | ⭐⭐ |
| 3 | `03-gateway-iam.ipynb` | AgentCore Gateway with IAM auth | ⭐⭐ |
| 4 | `04-gateway-cedar.ipynb` | Gateway + Cedar Policy Engine (permit/deny per target) | ⭐⭐⭐ |
| 5 | `05-gateway-jwt-cognito.ipynb` | Gateway + JWT auth via Cognito | ⭐⭐⭐ |
| 6 | `06-gateway-jwt-cedar.ipynb` | Gateway + JWT + Cedar (multi-tenant, per-department) | ⭐⭐⭐⭐ |
| 7 | `07-gateway-interceptor.ipynb` | Gateway + Lambda interceptor (dynamic filter injection) | ⭐⭐⭐⭐ |
| 8 | `08-full-governance.ipynb` | Full stack: JWT + Cedar + Interceptor + metadata filters | ⭐⭐⭐⭐⭐ |

## Quick Start

```bash
# 1. Clone the repo
git clone <repo-url>
cd fmkb-security-patterns

# 2. Open the setup notebook
jupyter notebook notebooks/00-setup.ipynb
```

Run all cells in `00-setup.ipynb` — it installs dependencies, downloads the preview SDK builds from S3, and extracts the service models. Then open any pattern notebook (01–08).

> **Note:** The setup notebook requires AWS CLI access to the `bedrock-managed-knowledge-bases-private-beta-assets` S3 bucket. It downloads ~900MB of preview SDK builds, extracts the service model JSONs (~1.3MB), and discards the rest.

## How the Preview SDK Works

The notebooks use three Bedrock services that require preview API models not yet in the public boto3 release:

| Service Client | Preview Version | Features |
|---|---|---|
| `bedrock-agent` | 1.42.78 | `MANAGED` KB type, managed connectors |
| `bedrock-agent-runtime` | 1.42.69 | `managedSearchConfiguration`, `agenticRetrieveStream` |
| `bedrock-agentcore-control` | 1.42.75 | Gateway, Policy Engine, Cedar policies |

These three preview builds each ship a full boto3 package with only their service's model updated — you can't install all three at once. Instead, `setup.sh` extracts just the service model JSON files from each build into `preview-models/`. At runtime, `shared/preview_session.py` loads them into botocore's data loader, so a single standard boto3 install supports all three services.

Every notebook imports the session like this:

```python
import sys; sys.path.insert(0, "../shared")
from preview_session import session

cp = session.client("bedrock-agent", region_name=REGION)          # control plane
dp = session.client("bedrock-agent-runtime", region_name=REGION)  # data plane
ac = session.client("bedrock-agentcore-control", region_name=REGION)  # gateway
```

> **When these features reach GA**, you can remove the `preview_session` import and use `boto3.client(...)` directly.

## Configuration

Edit the configuration cell at the top of each notebook:

```python
REGION = "us-west-2"
ROLE_ARN = "<your-kb-execution-role-arn>"       # IAM role for KB execution
GW_ROLE_ARN = "<your-gateway-role-arn>"         # IAM role for Gateway (patterns 3-8)
EMBEDDING_MODEL = "arn:aws:bedrock:us-west-2::foundation-model/amazon.titan-embed-text-v2:0"
S3_BUCKET = "<your-bucket>"
S3_ACCOUNT = "<your-account-id>"
S3_PREFIX = "<your-prefix>/"
```

### Required IAM Permissions

- **KB Role**: Bedrock KB execution, S3 read access to your document bucket
- **Gateway Role** (patterns 3-8): Bedrock AgentCore Gateway execution, KB invoke permissions
- **Lambda Role** (patterns 7-8): Lambda execution, CloudWatch Logs

## Architecture

```
┌──────────────────────────────────────────────────────────────┐
│                    Security Layers                            │
│                                                              │
│  Layer 1: Authentication (IAM / JWT / None)                  │
│  Layer 2: Authorization (Cedar Policy Engine)                │
│  Layer 3: Request Processing (Lambda Interceptors)           │
│  Layer 4: Target Configuration (admin-set KB + filters)      │
│  Layer 5: Document Scoping (metadata filters per query)      │
└──────────────────────────────────────────────────────────────┘
```
